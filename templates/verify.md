# 검증 레시피

QA·화면 캡처·재현이 앱을 실제로 띄우고 조작하는 방법. `config.qa.recipe`에 이 파일 경로를 적는다(CROSSGATE.md 15장). 앱이 바뀌어 맞지 않게 되면 보통 등급 작업으로 고친다.

## 실행
- 명령: (예: `npm run dev`)
- 준비됐다는 신호: (포트가 열린 것만이 아니라 실제로 쓸 수 있는 상태. 예: 로그인 화면이 뜨고 API가 200)
- 필요한 것: (로컬 DB, 시드, 환경 변수 이름. 값은 적지 않는다)

## 점검
실행 전에 막히는 것을 먼저 확인한다: (포트 사용 중, DB 꺼짐, 시드 없음 등과 확인 명령)

## 조작
- 화면 크기·기기: (예: 390px, 320px)
- 테스트 계정: (경로만. 비밀값은 적지 않는다)
- 안정적인 선택자: (역할·라벨·`data-testid` 우선. 좌표는 마지막 수단)

## 증거 기준
- 사용자가 실제로 가는 길로 한다(주소를 직접 치거나 내부 함수를 부르지 않는다).
- 화면에 보인 것뿐 아니라 저장·전송된 결과까지 확인한다.
- 다른 표면(다른 화면 크기, 모의 데이터, 다른 기기)에서 본 것은 통과가 아니다.
- 캡처는 바뀐 요소가 실제로 보이는 상태로 찍는다.
